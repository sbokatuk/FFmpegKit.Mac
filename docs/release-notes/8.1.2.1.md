First release of the native macOS bindings, superseding the `6.0.0.1-beta1` prereleases published under the same package ids.

## Platform change: Mac Catalyst → native macOS

The `6.0.0.1-beta1` prereleases were **Mac Catalyst** bindings (`net7.0-maccatalyst16.1` / `net8.0-maccatalyst17.2`) generated from arthenica's FFmpeg 6.0 xcframeworks. That source is archived and its release assets are deleted; no live source publishes Catalyst slices at all. From this release, `FFmpegKit.Net.<Variant>.Mac` targets **native macOS** — `net8.0-macos14.0`, `net9.0-macos15.0` and `net10.0-macos26.0` — built from the universal `macos-arm64_x86_64` slice of the actively maintained `sk3llo/ffmpeg_kit_flutter` builds (FFmpeg **8.1.2**), checksum-verified on download.

A Catalyst app cannot upgrade to these packages; a native macOS app is the consumer now. The old betas remain on nuget.org, frozen at FFmpeg 6.0.

## Highlights

- FFmpeg **8.1.2**, all eight variants, Apple silicon + Intel in one universal slice.
- Much larger bound API surface than the old prereleases: `FFmpegKitConfig`, `FFprobeKit`, `MediaInformation` and friends, plus `Task`-returning `ExecuteAsync`/`GetMediaInformationAsync` wrappers with cancellation, and ergonomic helpers (`Succeeded()`, enum-typed log levels).
- License metadata corrected: each package declares `MIT AND LGPL-3.0-only` (or `GPL-3.0-only` for `-Gpl` variants) and ships the license texts under `licenses/`. The old prereleases declared `MIT` while shipping copyleft binaries.
- Ships a `buildTransitive` `.targets` defaulting consumers to the `partial-static` registrar: the .NET macOS SDK's Release default (`managed-static`) fails at runtime on NuGet-delivered bindings with a missing `ObjCRuntime.__Registrar__` type. Set `<Registrar>` yourself to override.
- Verified by package-layout tests and an on-host e2e suite (13 checks: encode, probe, cancellation, log delegates, progress statistics) that consumes the packed package exactly as an app would.
